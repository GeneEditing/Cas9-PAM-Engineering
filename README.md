# Cas9-PAM-Engineering

Cas9-PAM-Engineering is **our pipeline for screening and ranking Cas9 PAM variants**. It integrates established models and tools—[PAMmla](https://github.com/RachelSilverstein/PAMmla), [ProGen2](https://github.com/salesforce/progen), [ESM-C](https://github.com/evolutionaryscale/esm), and [ColabFold](https://github.com/sokrypton/ColabFold). Our code prepares inputs, runs model inference, filters candidates, summarizes structural metrics, and produces the final ranking.

## Models and inference

| Model | Role in this project | Inference interface and entry point |
| --- | --- | --- |
| PAMmla (ensemble of seed 0/2/3 models) | Predicts combinations of six PAM positions | TensorFlow/Keras loads three SavedModels for batched inference and averages their predictions; [batch_predict.py](src/steps/01_pammla/batch_predict.py). PAMmla is a PAM prediction model, not a protein language model. |
| ProGen2-base | Scores full-length Cas9 sequences by likelihood | PyTorch loads the ProGen2 implementation and a local checkpoint; [score_progen2.py](src/steps/03_progen2/score_progen2.py). |
| ESM-C-600M | Scores mutation contexts | Hugging Face Transformers loads `AutoTokenizer` and `AutoModelForMaskedLM` from a local directory; [score_esmc.py](src/steps/04_esmc/score_esmc.py). |
| ColabFold 1.6.2 / AlphaFold2-ptm | Predicts structures for 38 candidates | Runs through the external `colabfold_batch` command; see step 6 in [pipeline.py](src/pipeline.py) for its parameters. It is a structure prediction tool, not a language model scorer. |

ProGen2 and ESM-C are the protein language models used in this workflow. The recommended way to invoke the models and screening scripts is through the main entry point:

```bash
bash run.sh check
bash run.sh run
bash run.sh status
```

The seven stages use, in order, `src/steps/01_pammla/batch_predict.py`, `02_shortlist/shortlist.py`, `03_progen2/score_progen2.py`, `04_esmc/score_esmc.py`, `05_joint_screen/joint_screen.py`, the external `colabfold_batch` command, and the ranking/export scripts under `07_final_ranking/`. A single stage can be run with `bash run.sh step N`, provided all preceding stages have been completed. For upstream model sources, resource paths, and license information, see [models/MODEL_CARD.md](models/MODEL_CARD.md).

## Installation, weights, and verification

The workflow requires Linux, Conda, a compatible NVIDIA GPU, network access, and sufficient temporary disk space. Environment specifications are in `requirements/*.environment.yml`. Generate the machine-specific path configuration with:

```bash
python3 configure.py
```

This creates the local `src/config.json`, which is excluded by `.gitignore`. Model weights are not distributed with the repository. Obtain them according to the upstream sources and license information in the [model card](models/MODEL_CARD.md), and place them in the directories listed there. `models/WEIGHT_MANIFEST.tsv` records the sizes and SHA-256 checksums of the files used previously. Verify local files with:

```bash
python3 models/download_weights.py check
```

The base address for historical direct links to the model weights is `http://1.12.219.134/1s2ZOEQeaKN3KC9a7qNF/`. `models/WEIGHT_MANIFEST.tsv` lists each file's path relative to this address, size, and SHA-256 checksum. After setting `CAS9_WEIGHT_BASE_URL`, `bash run.sh weights` downloads missing files from the manifest and verifies them. For example:

```bash
export CAS9_WEIGHT_BASE_URL="http://1.12.219.134/1s2ZOEQeaKN3KC9a7qNF"
bash run.sh weights
```

To use another server with the same directory structure, set `CAS9_WEIGHT_BASE_URL` to that server's address. The repository does not automatically use a default mirror. If the variable is unset and weights are missing, the download script stops and directs users to the upstream sources. Set `CAS9_GPU` to select a GPU. Existing environments can be specified with `CAS9_PAMMLA_ENV`, `CAS9_PROGEN2_ENV`, `CAS9_ESMC_ENV`, and `CAS9_COLABFOLD_ENV`.

## Inputs and MSA

The repository retains only the small reference inputs required by the workflow: `inputs/reference_candidates.fasta`, `inputs/reference_front38.tsv`, and `inputs/train_variants.txt`. Derived FASTA files, run logs, and results are generated by the workflow and are not committed.

**Before stage 6, prepare exact-query A3M files for the 38 candidates** and place them in `inputs/06_colabfold_msa/`. Replace `|` in a candidate ID with `_` in the filename; for example, `PAMmla_00002_MRACTQ.a3m`. The first query in each A3M file must exactly match the corresponding sequence in the candidate FASTA. These files can be generated with the ColabFold MSA search workflow or recovered from a trusted run archive. The MSA files are not distributed with this repository because of their size and insufficient source records. The current scripts do not search for missing MSA files online; missing or mismatched files cause the workflow to stop before expensive computation begins. See [data/README.md](data/README.md) for input details.

## Seven-stage workflow

1. PAMmla predicts approximately 64 million combinations of six PAM positions in batches.
2. Candidates are shortlisted by PAM score, distance from training variants, and sequence deduplication.
3. ProGen2-base scores full-length candidates.
4. ESM-C-600M computes mutation-context scores.
5. Joint screening selects 38 structure prediction candidates using a fixed reference table.
6. ColabFold predicts structures and structural metrics are summarized.
7. Final rankings are calculated, and candidate and mutation tables are exported.
